{{ _('How an artifact reaches a server policy') }}

{{ _('Nothing binds a file to a policy directly. The chain has four links, and the middle two are the ones people forget when they plan a migration:') }}

{{ _('server policy') }}  →  {{ _('Web Protection Profile') }}  →  {{ _('protection rule (XML / JSON / OpenAPI / gRPC)') }}  →  {{ _('the file object') }}

{{ _('The profile is what an operator actually opens on the appliance; the policy only names it. That is why every reference SATOM records carries the profile it travels through, and why the') }} {{ _('device audit') }} {{ _('groups by device rather than by file — a device is what a migration moves.') }}

{{ _('One exception, and it is the reason the profile is walked rather than assumed:') }} {{ _('Lua scripting') }} (cmdb/server-policy/scripting) {{ _('hangs off the SERVER POLICY itself and never passes through a profile at all. A policy that uses content routing can also bind SEVERAL profiles. Either shortcut — "the plan has one profile, so everything belongs to it" — prints a profile that does not mention the file.') }}

{{ _('So a recorded reference has three possible profile states, and they are NOT interchangeable:') }}

  • {{ _('a profile name') }} — {{ _('it arrives through that profile.') }}
  • {{ _('policy-level') }} — {{ _('walked, and it genuinely hangs off the policy (the Lua case). This is a FINDING, not a blank.') }}
  • {{ _('not attributed') }} — {{ _('nobody walked it for a profile. Re-walk the policy from the inventory page; until then the field is unknown, not empty.') }}

{{ _('Why the content is not in the configuration') }}

{{ _('FortiWeb stores these objects as a name plus an out-of-band file. The configuration you back up, export or clone contains the NAME only. Three consequences, all of them observed on real appliances rather than inferred:') }}

  • {{ _('A clone that copies configuration alone creates the object EMPTY. The appliance accepts the create; the rule that binds it then answers') }} -7694 {{ _('at runtime. The failure lands after the cutover, not during it.') }}
  • {{ _('Four of the seven types can be read back through a private endpoint. The other three answer') }} -20005 {{ _('to every shape of read that was tried — they are write-only from the API\'s point of view.') }}
  • {{ _('The device\'s own full-config backup does not carry them either. For those three types, an uploaded copy in SATOM is the ONLY path from one appliance to another. If nobody uploaded one, the content is gone with the box.') }}

{{ _('One name is validated by the firmware:') }} OpenAPI. {{ _('The object name IS the filename and the extension must be') }} .json {{ _('or') }} .yaml — {{ _('anything else answers') }} -20007, {{ _('so a clone that renames an OpenAPI object can break it.') }}
