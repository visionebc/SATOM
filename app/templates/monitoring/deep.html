Deep monitors

Does the service actually serve? Synthetic HTTPS against a server policy's published front-end, interface IP / link drift, processor load, memory usage and the proxyd daemon — each its own probe with its own thresholds, and each stored as a time series, because the signal is the value changing.

A page load never contacts an appliance — every row is read from the stored samples. Probing runs as a background job (Probe now) or on a schedule via the deep_monitor scheduled action. Interface data comes from the device cache refreshed by the hourly device_sync, so interface drift is detected at harvest cadence, not instantly. Processor load and memory usage read get system performance over the read-only CLI on FortiWeb and FortiADC; proxyd reads diagnose system top and is FortiWeb-only — it reports the memory consumed and free on the box, never the daemon's %VSZ (virtual size, which sums past 100 % across processes). Click any sparkline for 1 h / 24 h / 7 d / 30 d or a date range. Raw samples are capped per probe; beyond that the chart is served from hourly buckets (90 days) and daily buckets (2 years), so depth costs kilobytes instead of gigabytes.
