{{ _('Import a process') }}

A procedure written outside this console — a customer runbook, a plan kept in version control, a process built on the lab install — loaded as one file. It is checked by the same validator the editor saves through: a step this console would refuse to draw is refused here too, and nothing at all is written until every line of the file is accepted.

{{ _('File') }}
The key, the name, the ADOMs, every step and every arrow come from the file.
Leave this empty to import a new process. If the file's key is already taken, the import is refused until you type that key here — replacing rewrites the steps, the arrows and the settings of a plan somebody else may be about to run. Run history is kept: every run carries its own copy of the diagram it walked, so past reports keep saying what they always said, and a run parked on a manual gate resumes through its own snapshot.

{{ _('What is not read') }}

draw.io, BPMN and Visio files are named and refused, never half-read. A drawn box carries a shape and a caption; it does not carry the step kind or the parameters that make a step runnable — which URL, which command, which outcome each arrow follows. A shape-only import would produce a diagram that looks like your plan and cannot execute a single check.

Any process on this install can be downloaded as this exact format from its own page — Export XML.

{{ _('The format') }} a working plan, not a field table
  • key is permanent — run history and audit rows reference it.
  • Ticking no <adom> leaves the process a draft, visible in the Global console only. An empty list is never read as "everywhere".
  • Every parameter is an element, never an attribute. XML turns a literal newline inside an attribute into a space — only an escaped &#10; survives — so the readable way of writing a console script in an attribute is the lossy one, and it would arrive as a single line that is no longer the command its author wrote.
  • An arrow's branch is always, pass, fail or unknown — one arrow per outcome.
