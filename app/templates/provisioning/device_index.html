How far SATOM can take it — pick a mode

A factory Fortinet appliance boots into a first-boot dialog: admin with an empty password and a forced change. Nothing can reach its API until that dialog is completed, so “fully automatic” depends entirely on whether the hypervisor exposes a scriptable serial console. Proxmox does; a standalone ESXi does not, at any licence tier. That single fact is what the modes are about.

ModeWhat it does AdvantagesDisadvantages
Full Everything: address, DNS, machine, boot, walks the first-boot dialog over the serial console, registers the appliance, applies the profile. No human step. Repeatable and auditable end to end; every action lands in the run log. Proxmox only. Needs an API serial console. Most moving parts, so the widest surface for a mid-run failure — which is why rollback exists.
Semi Builds and boots the machine, then stops. You complete the first-boot dialog on the hypervisor console and press Resume. Works on every backend, including a free-licensed ESXi. The manual step is the one a human is genuinely needed for; everything else is automated. Not unattended — a run sits waiting until somebody acts on it.
DHCP Builds and boots; the appliance takes a lease, SATOM finds it at that address and carries on. Unattended without a serial console. Good on a build VLAN that runs DHCP. Needs DHCP reachable from the machine’s network, and the address it lands on is not the one you chose. Not every appliance takes a lease on its factory config.
VM only Creates and powers on the machine. Stops there, by design. Smallest blast radius. Useful when the appliance is configured by another team or a different tool. No address, no DNS, no registration — none of the rest of SATOM knows the machine exists until you onboard it.
Config only Skips machine creation entirely: reserves the address, writes DNS, registers the appliance and applies the profile against a machine that already exists. Needs no hypervisor at all. The path for physical appliances and for anything built outside SATOM. You built the machine, so its CPU, memory, disk and network are outside the run log and outside the audit trail.
Every mode is preflighted before it changes anything: SATOM asks the hypervisor what it can actually do and refuses a run it cannot finish, rather than discovering the limit after an address and a DNS record have already been committed.
