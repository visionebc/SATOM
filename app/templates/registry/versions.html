Preflight — would this payload be understood?

Before writing a payload built against one build to an appliance running another, ask. satom get api preflight <appliance> <object> <field>… answers from this matrix at the appliance's exact running build, and the answer unmeasured is a real answer — it is never reported as compatible.

  • ok — every field is present on that build.
  • unknown_fields — named fields that build has never been seen to serve.
  • absent — the appliance rejected that URN on that build.
  • fields_unknown — the endpoint exists, but it answered with an empty collection, so nothing is known about its fields.
  • version_unmeasured — that build has no evidence, while other builds of its line do. It is never answered from them: 8.0.4 is not 8.0.7. The line-granular answer is reported beside it, labelled, so the guard informs instead of merely blocking.
  • unmeasured — no evidence at all. Sweep an appliance on that build, or harvest its field schemas, before trusting a cross-build payload.
