13 · Scout and Path Diagnostics — operations beside Sentinel

Sentinel watches. The two operations tools answer an operator who already knows something is wrong: Path Diagnostics names the layer that is broken for one published service, and Scout (the operations assistant) explains it from everything SATOM already holds. The line between them is who starts it and what it owns, not “security versus troubleshooting”.

14 · Path Diagnostics — the ladder, and how it decides {% if _o.pd_enabled %}on {% else %}switched off on this site{% endif %}
  • The first FAIL stops the ladder. Every rung below it is skipped, never passed: a pool cannot be judged through a front door that never opened.
  • “Could not look” is never health. A rung that could not run is unknown; it does not stop the walk and it is counted as a blind spot.
  • A crash in the tool is not a fault in the path. A rung that raises is reported unknown with the error, never FAIL.
  • Read only. No rung writes; the only HTTP methods it will send are {{ _o.safe_methods }}, refused at the entrance otherwise.
  • Every rung records its vantage — this node, the appliance, or the collector — and the three are never merged: SATOM's path to a backend is not the appliance's.
  • No judgement is re-implemented. Each rung delegates to the module that owns its question (reachability, request timing, device health); the ladder owns only the order and the verdict.

What Scout decides, what it proposes, what it never does

Decides

  • which tool to call next, inside the round budget;
  • how to explain the evidence: which layer, why, what to check next.

Instructions to the model, not enforced by code: read the newest walk first and explain its verdict rather than contradict it; separate evidence from inference; treat a source that could not look as missing data, not health.

Proposes — a proposal is stored as pending; nothing happens until an operator approves it, with the permission the manual form already needs

Never

  • writes to an appliance or to SATOM's configuration — the tool catalog below has no writer;
  • runs a walk, deploys code or applies its own proposal;
  • sees more than the operator: every tool runs in the operator's session and applies the page's own gate (monitoring.view for Sentinel, owner-or-admin for jobs, audit.view for the audit log, ADOM visibility for appliances);
  • obeys text read from a device or a log: such text reaches the model wrapped as untrusted data, with an instruction not to follow it (a mitigation against prompt injection, not a proof).

Trail. Every exchange writes an audit row (advisor.send: provider, tool calls, redactions, external or not); a send outside the LAN also writes an export-log row; approving or dismissing a proposal is audited; a walk is audited with its report and job.
