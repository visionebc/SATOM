Response arming — which policies Sentinel may enforce on

A FortiWeb server policy does not name an IP list. It names a web protection profile, and the profile names the list. Until that reference exists, adding a source to Sentinel's list is accepted by the appliance, counts up on the device, and blocks nothing. The response runner refuses to act in that state rather than report a block it did not achieve — and it will not create the reference itself, because an agent that binds its own enforcement point can widen its own authority.

Arming writes ip-list-policy = {{ sentinel_list }} (or, for country blocking, geo-block-list-policy) onto the named policy's profile, creating the list if needed with a device-side block period. The two are armed separately on purpose — a country block affects every client in a market, and it stays a recommendation at any confidence even once armed. It reaches the appliance, so it is a deliberate POST and it is recorded in the audit log as your decision. It is safe to re-run: it is idempotent and it verifies by reading the profile back.
