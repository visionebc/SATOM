{# THE Admin Console menu. One definition, every Settings surface. This file is the single source: the console (settings/index.html) and every standalone Settings page (settings/sentinel.html) include it, so an entry added, renamed, re-icon'd or re-grouped here changes on all of them at once. Copying the markup into a page instead is how the horizontal strip that preceded this menu ended up with two entries pointing at one pane -- and nothing fails when two copies disagree: the operator simply gets a different menu depending on which URL they arrived by. Contract (all optional, all defaulted): nav_mode 'panes' -- entries switch a tab in THIS page (the console) 'links' -- entries navigate back to the console (a standalone Settings page, where the panes do not exist and a tab button would be a control that does nothing) nav_active the tab target ('tab-sentinel') or endpoint ('sentinel.docs') the caller is currently showing; it is drawn selected and its group is the one the server renders expanded is_admin whether admin-only groups are offered at all The tab TARGET is the identity of a section: the panes, the in-page links (#tab-auth), the URL-hash restore and tests/test_theme.py all key off it. Targets are therefore literal and NEVER translated -- only `label` goes through the translation call. (An identifier is not copy -- safeguards §68.) An item with `ep` instead of `t` is a link to a PAGE and is drawn with the leaving arrow. Integrations was the first entry to use it: it is a whole page of its own (/settings/integrations), not a pane of the console, and it had NO menu entry at all until the operator asked for one -- a page reachable only by typing its URL is a page that does not exist. Sentinel's Context and Response policy are PANES at the operator's request. The arrow is the only thing that distinguishes a row which replaces the whole page from one which does not, and every entry that leaves must carry it. Sentinel is a group of its own -- a pipeline with its own incidents console and architecture, not one knob under Monitoring -- and it sits below Monitoring & Alerts at the operator's request. Scout is a group of its own for the same reason and sits LAST, directly below Sentinel, at the operator's request. Filing it as one entry under Sentinel would have put a troubleshooting tool inside the security pipeline's section, which is exactly the confusion the two were separated to avoid: the clock starts Sentinel and it opens incidents; an operator starts Scout and it returns a location. A menu is where that distinction is first read. "Source of Truth & Backup" is a group for the same reason, added 2026-08-29 at the operator's request. It was ONE entry ("SoT & Backup") holding two unrelated authorities and a third that was not an authority at all, and the word "SoT" in its label was being read as covering all of them. Splitting the entries is the whole point: the CONFIGURATION SoT is the only thing this product calls a source of truth, the BACKUP SERVER is a destination and not an authority, and the repository this node downloads its own code from is a third thing again -- which is why the entry that was labelled "Git" now says "Software Update Repository" and stays under System, away from this group. A label is the only place that distinction is visible before a click. Software Update, High Availability, System Automations and System Backup & Restore moved here from Administrator > System on 2026-10-21 (FA-0005, operator request). They stay whole pages of their own, so they are `ep` entries with the leaving arrow, and each page draws this menu in `links` mode. System Backup & Restore sits with the backup surfaces; the other three are the node's own machinery and sit under System, Software Update next to the repository it pulls from. System Automations scopes its rows to the ADOM, so its entry (`adom`) carries `_adom` like the Administrator link it replaces: a hard navigation must not drop the ADOM. "Deploy Clone" joined that group on 2026-10-18 at the operator's request: it copies a whole installation's data (database, vault, SoT history) into another installation, i.e. the same estate the backup bundles carry. It is NOT "Clone / Migrate" under Fleet & Devices, which copies configuration between appliances -- the two labels must never converge. There is no "My Account" group: Security (2FA, recovery email, session) and Change Password moved to the user's own Profile page on 2026-10-23 at the operator's request. Every group here is therefore admin-only, and settings.index sends a non-admin to the Profile instead of drawing an empty console. Do not add a self-service group back: what belongs to ONE user lives on that user's Profile, and this menu configures the installation. 2026-10-23 restructure (operator): menus may nest ONE level ('sub' entries, a heading with its own entries). System > General holds General, Node TLS, Email & Alerts and Thresholds (the Monitoring & Alerts group is gone); Integrations is a group of its own with DNS Records and Hypervisors; AI holds Scout (Providers, Path Diagnostics, Architecture -- Path Diagnostics IS Scout's walk, app/services/scout_config.py) and Sentinel, divided as it was. The resolver list of DNS Lookup moved to the DNS Lookup page itself, so Network & DNS is gone too. Sentinel and Scout still sit LAST. Sentinel holds ONLY its configuration surfaces (operator, 2026-11-01: "what is configured stays in Settings, the rest goes to Operations"): Settings, Context (configuration however little it looks like it: it is the -35-point trusted-source weight, the largest single number in the scoring table) and Response policy. The incidents console, the overview (health, pipeline, score, demo lab, CVE mirror, decision log), the border blocklist (live entries and their release) and the architecture are Operations › Sentinel (partials/nav_sentinel.html). Do not add them back here. 2026-11-16 (operator): "Users" left Access & Identity -- it is Administrator > Users (/users/), and two menus offering the same page is one too many. Profiles, Authentication, Access Control and Vault stay. The same day the menu stopped being an accordion: every group and every sub-menu is drawn EXPANDED, a header still folds its own group for the rest of the visit, and nothing is remembered between loads.
