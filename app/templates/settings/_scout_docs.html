{{ _('Scout — architecture') }}

Scout answers one question — which layer is broken — and it answers it by walking down until something fails. It owns the ORDER and the VERDICT and nothing else: every rung delegates to the module that already owns its question, so there is never a second opinion in this product about whether a backend is reachable or a certificate is valid.

{{ _('Vantages, and why they are never merged') }}

This node sits on the management network. Its path to a backend is not the appliance's path to that backend, so a probe that succeeds from here proves nothing about the service and one that fails accuses the wrong device. Scout therefore keeps the vantages apart and labels every result with the one it came from; a rung it could only ask from one side says so rather than assuming the other.

{{ scout_docs.vantages.edge }} The only witness that separates firewall from reset from routing. From a socket those three are the same silence; the border wrote down which one it was.
{{ _('The four rules') }}
  1. The first failure stops the walk. Everything below it is reported as skipped, never as passing — a green rung under a red one is how a report gets read backwards.
  2. “I could not look” is never health. An unknown rung does not stop the walk and does not pass; it counts as a blind spot in the final verdict, which says so in words rather than issuing a clean bill.
  3. A rung that crashes is UNKNOWN, not FAIL. A defect in this module is not the appliance's fault, and painting it as one sends someone to restart a healthy device. The cost of the rule is that it also hides Scout's own bugs — which is why the ladder is walked against real hardware and not only against fixtures.
  4. Read only. Only the methods listed under Settings → Scout → Settings are sent, and the check runs at the entrance, before anything is contacted.
{{ _('Where Scout ends and Sentinel begins') }}

Not “security versus troubleshooting” — that line breaks the first time Sentinel raises a health incident. The line that holds is who starts it and what it owns: the clock starts Sentinel, it picks its own subject and it produces an incident; an operator starts Scout, hands it the subject and gets back a location. An incident may link into Scout with the object pre-filled. Scout never opens an incident.
