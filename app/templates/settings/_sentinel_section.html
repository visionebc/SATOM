1 · {{ _('What Sentinel does, stage by stage') }}

Every 3 minutes the sweep runs this pipeline left to right. Detection and response are deliberately separate acts: everything up to the policy gates is read-only observation, and the response runner — a separate systemd unit, not this web app — is the only component that can change an appliance, only when armed, and only through the gates.

2 · {{ _('The score, and what each band permits') }}

The score is plain arithmetic — no model touches it. It gates what Sentinel may do, so it has to be reproducible in the post-mortem that follows the one time it is wrong. What most designs get wrong is that subtraction is half the value: a blocked attack, a trusted scanner or a maintenance window pull the score down, because paging a human for a WAF doing its job teaches them to ignore the console.

observe <{{ bands.observe }} investigate recommend semi-auto ≥{{ bands.semi_auto }}

Below {{ bands.observe }} nothing is asked of anyone. From {{ bands.observe }} an incident is worth a look; from {{ bands.recommend }} Sentinel recommends an action to a person; from {{ bands.semi_auto }} an armed installation may act alone — if, and only if, every gate passes.
