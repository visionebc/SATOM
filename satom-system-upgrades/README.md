# SATOM system upgrades

Every SATOM release publishes a signed **update package**,
`satom-update-<version>.tar.gz`. It carries the application code and every
pinned Python wheel, so it upgrades a node with no network at all. This folder
is the index of those packages:

| File | What it is |
|------|------------|
| `latest.json` | The newest package: version, download URL, sha256, size, signing key. Nodes read this file. |
| `satom-update-<version>.json` | The same record for each release. |
| `README.md` | This page, with the table below. |

The packages themselves are **release assets**, linked from the table. They are
about 64 MB each; storing them in git would add that much to every clone per
release, and GitHub refuses files over 100 MB.

## Update a node that can reach GitHub (no download by hand)

The node downloads the package, checks its sha256 against `latest.json`,
checks the signature against its trust store, and applies it:

```bash
sudo satom execute update fetch          # dry run: what it would download
sudo satom execute update fetch --yes    # download, verify and apply
```

Or in the console: **Settings → Software Update → Offline update package →
Check for a newer package online → Download & stage**, then read the preflight
and press **Apply**.

Nothing is fetched unless you ask: SATOM does not poll this feed on its own.
`SATOM_UPGRADE_FEED=<https-url>` points a node at a mirror of `latest.json`.

## Update a node with no internet

1. Download the package (and its `.sha256`) from the table below on any
   machine, copy both to the node.
2. In the console, **Software Update → Offline update package → Upload &
   check**, then **Apply**. Or from a shell, in the folder with the files:

```bash
sha256sum -c satom-update-<version>.tar.gz.sha256
sudo /usr/local/sbin/satom execute update package ./satom-update-<version>.tar.gz --yes
```

Nodes installed before 2.5.0 need two one-time steps first (trust the release
key, record a git baseline): see `docs/offline-update-packages.md` §4.1 or the
*Update an installed node* section of the downloads page. From 2.7.0 on,
`sudo satom` works on openSUSE and RHEL too (`/usr/bin/satom` link); on older
nodes use the full path `/usr/local/sbin/satom`.

## Signing key

Packages are signed with `satom-release-2026`
(`SHA256:cYv9NxiJjMn/K6srKxXg2kdvROP2g6fzgfMXU6sxPyA`). Its public half ships
in `deploy/update-keys/` and with every release.
