Everything the console does — plus what it doesn't

A full mirror of the FortiWeb GUI workflow, backed by a database, an audit trail and automation the appliances themselves can't offer.

🧭

Server Policy management

Policy table with editable detail forms, minimal-diff saves, and guided clone / migrate across devices with pre-flight checklists and safe cascade delete.

🛡️

Web Protection (WAF)

Signatures editor with per-signature exceptions, 166 curated object kinds, and guided WAF exceptions with template locks and lifecycle tracking.

🧩

Spec-driven object editor

Any of ~500 registry endpoints editable through one form engine — stacked slide-over panels, create-references-in-place, dry-run previews on every write.

📦

Device operations

Discovery, deep capture, config backups with SSH fallback, restore vault, firmware upgrade runbooks and an SSH console with read-only presets.

🔐

Certificate lifecycle

Central Certificate Manager — issuance via ADCS or ACME, revoke-on-supersede policy, expiry sweeps, SNI policies and REST deploy to FortiADC.

⏱️

Automation & change control

Cron-style scheduled actions, Change Requests with maintenance-window approval gates, and background jobs with pause / resume / stop.

🗂️

Git source of truth

Every device's configuration is harvested on schedule and versioned in git — drift detection, A→B diff viewer and point-in-time restore included.

🌐

Multi-product workspaces

Global, FortiWeb and FortiADC workspaces with per-browser-tab product context, plus FortiAnalyzer log & event integration over JSON-RPC.

Versioned /api/v1 with scoped bearer tokens (read ⊂ write ⊂ admin), owner-capped and product-bound — deliberately narrow and read-biased.

High availability & layered backups

Two-node active/standby clustering is built into the installer — not bolted on.

🔁

Primary / standby pair

PostgreSQL streaming replication with enforced TLS and mutual certificate authentication; application data rsynced to the standby every 5 minutes.

🔑

One-paste cluster join

The primary generates a single join key at install time; paste it on the secondary and replication, shared secrets and node certificates configure themselves.

🧯

Defense-in-depth backups

Live database, portable backup bundles, git-versioned device configs and an external SFTP backup server — four independent copies across failure domains.

Installation

One interactive installer, two modes. Debian 12, Python 3.11, PostgreSQL 15 — everything else is handled for you.

Online

Connected install

Fetches OS packages and Python wheels as it goes. Prompts for IP, port, admin password and standalone / cluster mode.

# as root on a fresh Debian 12 host
./install-ofortmaut.sh
Offline

Air-gapped install

A self-contained bundle — all .deb packages, Python wheels and the application — for hosts with no internet access. Auto-detected when bundle/ is present.

tar xzf ofortmaut-offline-<ver>-debian12-amd64.tar.gz
cd ofortmaut-offline && ./install-ofortmaut.sh
  • Checks required packages, installs what's missing, warns on outdated versions
  • Standalone or two-node cluster — the secondary joins with a single pasted key
  • Each node mints its own TLS certificate during installation
  • Ships with a hardening guide and a granular sudoers policy for change approval
