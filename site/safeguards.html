Safeguards & guard rails

SATOM writes to production appliances, rewrites its own checkout, installs its own dependencies and reloads its own web server. Every one of those is a way to lose data or lock yourself out. This page is the catalog of what prevents that — and every item ships today.

Design rules

Six rules every guard follows

The failure mode this product defends against hardest is not a missing guard — it is a guard that silently takes the wrong branch and reports success.

📣

Fail loud

A guard that cannot do its job aborts the operation. No step is allowed to report success while doing nothing.

📸

Snapshot first

Nothing destructive runs before the previous state is parked somewhere that survives the destruction.

✅

Verify, then commit

Every self-mutation is followed by a real check — import smoke, config test, HTTP health — and auto-reverts on failure.

🔒

Allowlist, never free-form

Package names, provider fields, document slugs, remote filenames, device verbs — closed sets, re-validated at the privileged end.

✍️

One writer

On a cluster the primary owns every replicated write. The standby refuses rather than producing state its own sync will undo.

🎛️

Operator edits outrank seeds

Tunable data is seeded insert-only into the database, so an upgrade never resurrects what an operator deliberately removed.

🌳 Git history

The repository carries two assets: the application code and a diffable per-device configuration snapshot, refreshed on a schedule. The git remote is a distribution point, not a custody point — and the dangerous moment is not the outage, it is the return.

GuardWhat it prevents
Commit preservation before reset --hardLosing commits that exist only on this node. They are parked on permanent refs/backup/* refs, a dirty tree included. If they cannot be parked, the update aborts — a deferred update beats silent history loss
Unpushed-commit alertA push failing quietly for days. The signal keys off the age of the oldest unpushed commit, not the count, because one commit stuck for three days is worse than twenty in the last hour
Repository bundlesTotal loss. One verifiable, clonable file with the entire history and every ref — kept on the node, mirrored to the standby, pushed to an external backup server in a different failure domain, and downloadable from the UI
Deletes are primary-onlyDeleting a bundle on the standby, where the next data sync would restore it and make the UI look broken
Insert-only catalog seedsA deploy overwriting endpoint or provider rows an operator corrected. A vendor moving a REST path stays a row edit, not a release
📦

Bundles are verifiable offline. git bundle verify proves integrity, git clone <bundle> rebuilds the whole repository, and a checksum sidecar lets you trust a copy before you use it. No server, no daemon, no embedded credentials.

⬆️ Updates & dependencies

The web process never mutates the installation. It writes a request; a privileged runner picks it up and does the work — so the update path cannot be reached by whatever reaches the web app.

1

Snapshot

Current revision or package version recorded

2

Apply

Update code or install the pinned version

3

Smoke

The application must still import

4

Health

Restart, then a real HTTP check

5

Revert

Any failure restores the snapshot

  • Dependency upgrades are curated-only. The allowlist is the application's own library inventory, validated when the request is queued and again inside the privileged runner, with name and version pattern checks. There is deliberately no "install any package" path from the browser — that would be remote code execution as the service account
  • Rollback is one click, because the previous version is recorded per node before the change
  • Per node by design — the virtualenv is not replicated, so the card names the node it will affect; the dependency pin is committed from the primary only, so the next code update does not undo it

🛡️ Privilege boundary

The application does not run as root. What needs root is reached through a queue, not a function call.

  • The service runs under a dedicated unprivileged account; its sudo grants are an explicit short allowlist, not ALL
  • The account is pinned in a systemd drop-in, not in the shipped unit file, so a self-update that replaces units cannot silently hand the application root again
  • The privileged runner is triggered by a watched request directory — the web process submits a typed request and can never pass a command
  • Every HA guard probes the node's role through a path that works unprivileged. The obvious probe needs root, and unprivileged it returns empty — which made guards take the "not primary" branch while the service reported success. That class of silent failure is now impossible by construction

⌨️ The operator console

A tool for the node whose web interface is the thing that broke. Everything about it is shaped by that one requirement — and by the fact that it is invoked with elevated privilege.

GuardWhat it prevents
No framework imports at module levelA diagnostic that cannot run when the installation is broken. Commands that genuinely need the application import it inside the function and degrade with a stated reason. The test suite checks this by parsing the source, because a stray import would not be noticed until the day it matters
A root-owned copy outside the application treePrivilege escalation through the tool itself. The application tree is owned by the service account; a launcher that executed code from it would let a compromised web worker rewrite what an administrator runs under sudo. The installer verifies owner and mode, and refuses a symlink
Re-installed after every updateA stale console. It lives outside the tree, so a code update does not reach it — the installer, the update runner and a repair verb all refresh the copy
Refusal instead of a tracebackAn operator guessing. A state-changing verb run without privilege prints the full command line including arguments and a distinct exit code — retyping remembered arguments is how the wrong ones get typed
Read commands never writeA diagnostic that creates the drift it reports. Repository status runs without optional locks and byte-code writing is disabled during a compile check, because both were silently taking ownership of files away from the service account
Destructive verbs must be declaredAn irreversible action with no confirmation. A command marked destructive that does not require explicit confirmation fails the test suite
The tree is data, not code pathsA command with no help text or no declared privilege class. The parser, the help, completion, the privilege gate and the JSON renderer all read one structure, and an incomplete entry breaks the build
The output path cannot crashDying while printing. Decoration is stripped for pipes, the character table folds to ASCII at the render boundary, and the stream is hardened for content the table cannot know about — a hostname, a certificate subject, a log line. A serial console once killed a command over a dash in a title
Refuses to control its own runnerRe-entering the privilege boundary sideways. The privileged runner and the database engine are deliberately not controllable from the console; disabling the runner is refused outright, because it would leave every queued update pending with nothing reporting it

⚖️ Two-node correctness

A cluster multiplies the ways state can diverge. Each guard here exists because divergence, not downtime, is the expensive failure.

GuardWhat it prevents
Update and promotion refuse on the standbyTwo nodes rewriting the deployment — split brain
Backup and bundle deletes refuse on the standbyDeletions the mirroring sync immediately undoes
Data sync runs on the standby and pullsThe primary ever pushing over a peer; the job is inert anywhere else
Forced command on the peer keyThe synchronization key being usable as a shell
Peer identity matched against the real hostnameFalling back to the first configured node and synchronizing a node against itself — an incident this project actually had after a rename
Best-effort writes on the replicaA sign-in failing on the read-only standby just because it could not stamp a timestamp
Authenticated TLS between nodesCleartext or unauthenticated node-to-node calls; database replication refuses non-TLS and certificate-less connections outright

🧯 Writing to appliances

This is the part that can take a customer offline, so it has the most gates.

  • Read-only means read-only. Every line of a device command is validated, not just the first — a pasted read followed by a write cannot sneak past a legitimate opening line
  • Dry-run, then apply. Writes are computed as a minimal diff and shown before anything is sent, with a full audit entry on the way out
  • Lease locks. One operator holds a lease per object, refreshed by heartbeat, re-entrant for the same user, and expiring on its own if a browser tab is abandoned — so a closed laptop never blocks an object permanently
  • Change requests gate the dangerous ones. A firmware upgrade refuses to flash unless its change request is approved and the clock is inside the maintenance window — re-checked at fire time, not only when it was scheduled. Every transition stamps a timeline event
  • Per-device configuration restore is still dry-run gated. Listed here as a limit, not sold as a feature

📜 Certificates

  • An import cannot take the UI down. The PEM is parsed, the private key must match the certificate, the web server configuration is tested, and the files are rolled back and reloaded if it is rejected
  • ACME signing runs in a minimal environment. The application's own environment carries encryption keys and the database URI; the signer is handed a curated passthrough instead of inheriting it. Provider credentials travel as environment variables, never on the command line
  • Secrets are redacted from the stored log and from the command preview — and the command is a plain argument vector, never a shell string, so there is no injection surface
  • The renewal journal is node-local, deliberately outside the replicated set: the node that fails to renew may be exactly the one with a read-only database. Each node publishes its own journal, and the page shows both
  • A failed renewal is its own alert — escalating to critical after three in a row — instead of being implied weeks later by an expiry warning

📁 Files from outside

  • Every external listing, preview and download resolves through a name validator — path traversal and forged names return a 404, not a file
  • Firmware pulled from a backup server is checksum-verified on arrival; backup bundles carry a checksum sidecar
  • Copies are spread across distinct failure domains on purpose: node, standby, external backup server, and your own download. A single host loss can never take out every copy

🎨 Operator-supplied appearance

Letting an operator recolour the console means accepting operator input into a stylesheet that carries the page's own security nonce. The entire design of the theme engine follows from refusing to do that naively.

GuardWhat it prevents
Tokens, never raw CSSStored CSS injection. One closing brace ends the intended rule and starts an attacker's. The editable surface is a closed list of design tokens the stylesheet already exposes — not a text area
Validated by kind, plus a forbidden-character listA value that is syntactically a colour but semantically a payload. The two layers are not redundant: the colour pattern is narrow enough to stand alone, but the shadow and font classes accept letters, digits and parentheses — enough to smuggle an external reference past a per-type check
Gradients parsed structurallyThe same, for a value type that legitimately contains commas, percentages and nested functions
Re-validated when emittedTrusting the database as a boundary. A restore, a replica or a direct SQL session can put a value in the table that never passed the form
Contrast audited with alpha compositionAn unreadable console. Every text/background pair is scored; below the legibility floor the save requires an explicit acknowledgement. The shipped palettes are asserted in the test suite, so a change that degrades them fails
Three independent ways backLock-out. Revert to the shipped look, activate a built-in, or run one console command. Built-ins cannot be edited or deleted, and deleting the active theme falls back instead of leaving the console unthemed
The token registry is generated from the stylesheetAn editor that silently loses a control. A hand-maintained list is a copy; the build fails if the two drift
Every theme declares its own brand rampsAn amber console painting blue buttons. A theme stores only its overrides, so a theme that omits a gradient inherits the stylesheet's — which is correct for the default and wrong for every other palette
Gradients are refused where a browser would drop themA border that disappears instead of changing colour. Paint properties accept a ramp; border-color and friends discard it silently
🌓

There is no dark console, and that is stated rather than implied. Around a hundred and forty status tints are still literal values in the stylesheet, so a dark canvas would leave islands of light. The public site does offer a dark theme — its palette was fully tokenised first, which is exactly the work the console still owes.

📚 Documentation leaving the building

The manuals are written with real addresses, hostnames and node names, because that is what makes them useful to the operator. Publishing them is therefore a data-loss risk in the opposite direction.

GuardWhat it prevents
Redact, then scan the output, then abortA leak with a receipt. The publication step rewrites known identifiers and then re-scans what it produced; a hit stops the build naming pattern, file and line. A warning inside a publishing pipeline is a leak that was announced and shipped anyway
Publication is opt-inA new manual being published by the mere act of existing. A document absent from the register is not published
One rendered copy on the internetA second rendered copy running on a management server — which is exactly how an unauthenticated route once served internal addresses to anyone who could load the sign-in page
A single shared registryThe generator and the application drifting into two different ideas of what is public. Both read one module, and the test suite fails if either re-declares the list, the redaction table or the scanner
The scanner is asserted against real inputA round-trip that proves nothing. Narrowing the redactor and the scanner together leaves the pair self-consistent and green while publishing the identifier. The test asserts the raw source still contains something the scanner must catch
Placeholders that cannot vanishAn invisible redaction. Angle-bracket placeholders were being parsed as unknown HTML elements and rendered as nothing, silently deleting a word from the sentence
Product identifiers are deliberately not redactedMutilating documentation without hiding anything — workspace keys and URL segments are part of the product, not the estate
Manuals readable with no networkA published-only manual on an isolated management network. The operator console prints any document straight to the terminal, which is what makes a single published copy safe

👁️ Content & presentation

A whole class of failure produces a perfect HTTP response, a complete document, a clean security scan — and a blank page. These guards exist because that happened.

GuardWhat it prevents
Content is visible by defaultA page that renders nothing when its script is blocked, stale or filtered. Hiding is applied by a blocking snippet in the document head and only for the duration of the animation
The hiding flag is withdrawn if the revealer never runsThe inverse failure — the head arms the concealment and the script that would undo it fails to load. A timeout removes the flag
Any visible pixel reveals a sectionA threshold expressed as a fraction of the element rather than the viewport: a document taller than eight screens can never reach it, so the longest and most important manuals were the ones rendering at zero opacity
Assets carry a content hashA visitor with fresh markup and a cached script — which reads as "this feature is broken", not "your cache is old". The hash is derived from the file, never from a version constant somebody can forget to raise
The product icon is served on every surfaceA rebrand that never reaches the browser tab. The bare icon path is answered explicitly, because a browser requests it on its own and caches the 404 — a missing route is precisely why an old icon outlives a rename
No live template serves the previous brandAssets whose filename mentions neither the old nor the new name, and which therefore survive every text search. One had outlived three renames on the first page shown after sign-in
🔬

This class cannot be caught by reading the HTML — the HTML was correct every time. It is verified by measuring the computed style in a real browser, on the real published pages.

📡 Monitoring that can say no

A monitoring page earns its place by being able to deliver bad news. Several of these guards exist because a screen was structurally incapable of it.

GuardWhat it prevents
The health badge grades four signalsA badge that can never turn red. Scoring only on capacity headroom meant an appliance that was powered off, whose harvest had failed for days and which had nothing cached, still rendered healthy. Harvest, cache age, probes and capacity are now graded together and every failing signal is printed
unknown ranks below okAbsence of measurement reading as health
A disabled probe is not a passing probeSilencing a monitor to clear a board. Switching one off removes coverage, and the card says so
The page and the mailbox share one ladderTwo surfaces disagreeing. Before this, the alert side was a bare network probe — appliances answered their port for a week with a dead harvest and never produced a single mail
A page load never opens a connection to an applianceA monitoring screen that hangs when the thing it monitors is down. Every view is served from the database; probing is a background sweep or an explicit action
A workspace never shows the manager's infrastructureNode names and infrastructure addresses appearing inside a product view. The data endpoints omit those sections outside the manager workspace and the infrastructure routes answer 403 — a hidden card whose endpoint still answers is hidden, not scoped
Fleet-wide actions resolve their targets in the requestA sweep launched from one product workspace opening connections to appliances of another. Worker threads have no workspace of their own, so the target list is resolved where it exists and passed in
Absence of data is never healthA zero transaction count on a saturated service. A zero is cross-checked against live sessions before it may grade healthy; an empty bucket list is an error; a watched port that disappears is named, not dropped from a shorter list
Recurring work is silent unless it failsAlert fatigue from the system announcing that it is doing what it was told to do. A sweep raises nothing on success — and the failure is the one thing the page itself cannot show, because stale numbers look current
Stale work is swept out of the progress feedA control the operator cannot use. An abandoned task offering a Stop button that can never work teaches people that the progress area lies — and then the one that matters is dismissed too
The test suite cannot write to the live ledgerRunning the tests on a node inventing phantom background tasks in production — which is what was reappearing every time the product was worked on
Parked appliances are skipped, not failedA permanent critical alert about machines nobody expects to answer. A run whose entire target set is parked reports skipped, which does not feed a failure streak; a manual run still reaches them

🔔 The alert catalog

All of the above is only useful if silence means healthy. Thresholds and recipients live in settings; each signal has its own cooldown.

SignalFires when
Certificate expiry / errorThe service certificate is inside the warning window, or cannot be read
Renewal failedA renewal attempt failed — critical from three consecutive
Unpushed commitsLocal history has been waiting to reach the remote for too long
Behind / divergedThe checkout trails the remote past the limit, or both sides moved
Backup missing / stale / errorNo backup at all, none recent enough, or the check itself failed
Device healthAn appliance is degraded or critical on the same four-signal ladder the page uses — one finding per device, with every failing signal as a line in the message, plus a live network probe the page deliberately does not have
Device errorThe appliance list, or one device's health roll-up, could not be read at all
Scheduled action failingA scheduled run has failed repeatedly. Only scheduled runs count — a manual run is already on someone's screen, and mixing them hides the case where the scheduled path is broken while manual runs pass
Scheduled action overdueAn enabled action whose next run came and went. Without this, a dead scheduler looks perfectly healthy — it produces no failed runs to count
Drift errorThe configuration drift comparison could not run
Engine errorThe alert engine itself failed — the guard on the guard
⚖️

Severity is part of the quiet-period key. A device or an action that degrades from warning to critical inside the cooldown still reaches the operator — a fixed key would suppress precisely the escalation the alert exists for. And a finding is filed under the workspace of the appliance, never the session that happened to compute it, so a load-balancer alarm never rings in the firewall workspace.

📦 Fresh installs

The guards travel with the code: a node installed from the connected path or from an air-gapped bundle has the history guard, the dependency allowlist, the pinned service account, the restricted peer channel and the certificate rollback from its first boot.

What does not arrive armed is everything that lives in the database. Seeds are insert-only and operator edits outrank them, so nothing is scheduled on the operator's behalf: a brand-new install has no scheduled actions and no alert recipient. Its signals are computed and delivered nowhere, its source of truth is never refreshed, and no repository or database backup is ever produced.

That is a deliberate trade — the product never invents schedules against live appliances — and it is also the most common way an install ends up unprotected. The install manual ships the recommended minimum set; arming it is part of finishing the install, not an optimisation.

An air-gapped bundle carries one extra caveat: it is a snapshot of the product at build time, so the guards inside are the ones that existed then. The bundle records its own version, and it carries the ACME client and the privilege-escalation and SSH packages, because a host with no network cannot fetch them — and a missing one used to abort the install after the service account had been created, exactly the half-applied state the verify-then-commit rule exists to prevent.

🚧 Known limits

Published on purpose. A safeguards page that lists only strengths is marketing, not documentation.

  • Per-device configuration restore is dry-run gated — no live canary round-trip yet
  • A publicly-issued wildcard certificate is not auto-renewable from the node; certificates issued by the internal CA are
  • The firmware manifest in the source-of-truth repository is maintained by hand
  • Co-locating the git server and the standby on one host is a real single point of failure. The external bundle exists because of it — it mitigates rather than fixes it
